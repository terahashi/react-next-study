✅パスワード付きのログインフォーム
LoginFormApp.jsx


------------------------------------
・今回の「Supabase」の機能・名称
① Supabase➡️サーバーの役割,サービス全体の名称であり、インフラ(サーバー環境)全体をまるごと貸してくれる大きな枠組み
② Supabase Auth➡️API の役割,会員登録やログイン判定、パスワード検証、**JWT(通行証)**の発行をしてくれるプログラム(API)
③ Supabase (PostgreSQL)➡️データベース(DB)の役割,ユーザー情報(メールアドレスや暗号化されたパスワードなど)が大切に保存されている金庫
⬇︎
Supabaseのみで「サーバー、API、DB」を使える優れもの。
------------------------------------





🍎用意するもの

💡1: フロントエンド(画面側)
・役割:
ユーザーがメールアドレスとパスワードを入力し、送信ボタンを押してリクエストを送る場所。

・使うもの:
今回使う➡️React





💡2: バックエンド(APIサーバー)
・役割:
「メールアドレスが存在するか」
「保存されているハッシュ化パスワードと一致するか」
合っていれば「ログイン成功の鍵(トークン や セッション)」を発行して画面側に返す

・使う技術(言語/フレームワーク): Supabase Auth、 Node.js (TypeScript)、 ,Go (Golang)、 Python (Django/FastAPI)、 Ruby (Ruby on Rails)、 PHP (Laravel) など。
今回使う➡️Supabase Auth
Supabase Auth➡️APIの役割






💡3: データベース(DB)、Supabaseの管理画面内で操作する作業
・役割:
登録されている「メールアドレス」や「暗号化されたパスワード」を保存しておく。

・使うもの:supabase (PostgreSQL) , MySQL, PostgreSQL, MongoDB など
今回使う➡️Supabase (PostgreSQL)
Supabase (PostgreSQL)➡️データベース(DB)の役割




💡4: 認証の仕組み(鍵のやり取り)
・役割:
一度ログインしたあと、ページを移動しても「ログイン中」を維持するための仕組みです。


・使う技術:
JWT(JSON Web Token): ログイン成功時にサーバーから送られる「デジタル通行証」。React側はこれを受け取って保持しておく。
Cookie / セッション: ブラウザに安全に鍵を保存する仕組み。











🍎どこでサーバーを動かすの？
実際にこれらをインターネット上に公開・運用するときは、以下のようなクラウドサービス(サーバー)を使う。

👾API・DB(バックエンド)を置く場所:
・使うもの: Supabase, Render, AWS, Google Cloud, Heroku など
今回使う➡️Supabase。
Supabase➡️サーバーの役割
Supabase 自身が「APIプログラムを動かすサーバー」を最初から用意してくれている！


👾画面(React)を置く場所:
Vercel(バーセル), Netlify(ネトリファイ)など


・Supabase, Render、AWS、Herokuとは？
インターネット上にある「プロ用のパソコン(サーバー)を貸してくれるサービス」のこと。


・そこに何を入れる(置く)？
API(プログラム) ➔ 「ログイン判定」などの計算をするコード
DB(データベース) ➔ ユーザー情報が入ったデータ




・従来の作り方(自前でサーバーを作る場合)
Render や AWS でサーバーを借りる
Node.js や PHP で「ログイン判定用のプログラム(API)」を自分で書く
サーバーにプログラムを置いて 24時間動かす










🍎全体の作成手順(5ステップ)







💡【ステップ1】画面の見た目とUIロジックを作る(★今ここ！)
まずは React だけで、ユーザーに見える画面(フロントエンド)を完成させます。


使うもの: React のみ


・やること:
入力フォーム(メールアドレス、パスワード)の作成
例題11でやる「パスワード表示/非表示」切り替え機能
入力漏れなどをチェックする「バリデーション機能」
送信ボタンを押した時の「ローディング表示(ぐるぐる)」などの見た目の状態(State)管理












💡【ステップ2】Supabase(バックエンド)の準備をする
ここでバックエンド(API・認証・データベース)を準備します。コードを書く必要はなく、ブラウザ上でポチポチ操作するだけです！


・使うもの:
Supabase(ブラウザ画面)


・やること:
Supabase に無料アカウント登録
プロジェクト(自分専用のバックエンド環境)を1つ作成する
「Authentication(認証機能)」をオンにする













💡【ステップ3】React と Supabase を接続する
Reactのプロジェクトに Supabase の公式ライブラリを入れ、接続設定を行います。



・使うもの:
React, Supabase



・やること:
1:npm install @supabase/supabase-js でライブラリをインストール
Supabase の管理画面から「URL」と「APIキー(鍵)」をコピーして、React側に貼り付ける(これだけで接続完了！)

2:「.env.localファイル」の作成。
中身は「URL」と「APIキー(鍵)」を入れる。

3:「supabaseClient.jsファイル」の作成。
Supabaseと通信するためのクライアントを作成してエクスポートする。
詳しくは「supabaseClient.jsファイル」を見よう。














💡【ステップ4】会員登録＆ログイン処理を呼び出す

ステップ1で作ったフォームの「送信ボタン」を押したときに、Supabase の認証APIを呼び出すコードを組み込みます。



・使うもの:
React, Supabase API




・やること:
ログイン処理 ➔ supabase.auth.signInWithPassword({ email, password }) を実行
会員登録時 ➔ supabase.auth.signUp({ email, password }) を実行
成功したら「ログイン成功！」画面に切り替える(アーリーリターンやState切り替え)
裏側で自動発行された JWT(通行証) を受け取ってログイン状態を保持する




‼️「ログイン処理」の追加
1:handleLoginイベントを追加
2:supabase.auth.signInWithPassword({ email: formData.email, password: formData.password, }) を実行。
3:テスト用ユーザーで認証し、isLoggedIn の State を true に切り替えて画面遷移
4:バックエンドから送られた JWT(通行証)を受け取ってログイン完了！




‼️「会員登録の処理」の追加
1:handleSignupイベントを追加
2:supabase.auth.signUp({.  email: formData.email, password: formData.password, })  を実行。
3:テスト用ユーザーで新規登録し、 alert('新規登録が完了しました！')でブラウザ通知表示する
4:新規登録完了





‼️「アカウントをお持ちでない方はこちら」をクリック」と、「すでにアカウントをお持ちの方はログイン」のモード切り替えUIの追加。
「アカウントをお持ちでない方はこちら」をクリック ➔ 画面が「新規登録モード」に切り替わり、ボタンも「新規登録」1つになる。
「すでにアカウントをお持ちの方はログイン」をクリック ➔ 画面が「ログインモード」に切り替わる。ボタンも「ログイン」1つになる。













💡【ステップ5】セッションの保持(ログインしたらそのままログインし続ける処理)を、実装しよう。


・ここまでの状態は...
これまでは「ログイン」に成功したらSupabaseで認証が成功していました。
しかし「リロード(画面更新)をすると、Reactのメモリがリセットされ、キーをどこかに落としてしまった扱いになり、
また受付(ログイン画面)に強制送還されてしまう。」



・使うもの:
React, Supabase API


・やること
画面のリロードがされても「(ログイン画面)に強制送還されないようにしよう。」




1: ページ読み込み時の「キー情報でのログイン済/否の初回チェック」
getSession() ＝ ページ読み込み時の「初回チェック」。
リロードされたら、画面を描画する前にポケットの中を確認。
キーが残っていれば、ログイン画面をすっ飛ばして一瞬でログイン成功画面を表示します。

✅⬇︎Supabaseが自動で作って返してくれる【sessionオブジェクトの構造】➡️ setUser(session.user)で使用する。
session = {
  access_token: "eyJhbGci...", // 暗号化されたトークン
  expires_at: 1722800000,     // 有効期限

  //ここに「user」というプロパティが最初から入っている！
  user: {
    id: "9b1deb4d-3b7d-4bad...", // ユーザーごとに割り振られる固有ID
    email: "test@example.com",   // ログインしたメールアドレス
    created_at: "2026-08-04...", // アカウント作成日時
    role: "authenticated"        // 認証済みフラグ
  }
}



2: キー情報の24時間監視(onAuthStateChange) ➡️ ログイン・ログアウトの変更をリアルタイム監視
onAuthStateChange() ＝ ログイン・ログアウト時の「リアルタイム監視」。
「キーが新しく入った(ログイン)」「キーが消えた(ログアウト)」という変化を常時監視し、自動で画面を切り替えます。





3: ログアウト処理(signOut)
supabase.auth.signOut(); ＝ 鍵を破棄する「後始末」。
ボタンを押すと、画面を切り替えるだけでなくポケットの中のキーを破棄します。















💡【ステップ6】ログイン限定ページ(マイページなど)を作る
ログインしているユーザーだけが見られる特別なページを作成します。


・使うもの:
React, Supabase API


・やること:
JWT(通行証)を持っているユーザーだけがアクセスできる「マイページ」を作成
「ログアウト」ボタンを押したら JWT を破棄してログイン画面に戻す処理
